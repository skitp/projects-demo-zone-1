I think there is an opportunity to make stability more predictable by design by revisiting the Platform–Domain handshake and decoupling the two release lifecycles.

Given our priority with regards to sustainable stability, I'd love to further discuss on this with you and see how we can prioritize this. 

Today: The current model couples Platform and Domain releases, requiring Domains to repeatedly merge, integrate, and regression-test Platform code. Multiply each Platform code to # of Domains consuming. This consumes capacity and, more critically, makes stability dependent on every Domain staying current with Platform fixes and patches, a model that is increasingly difficult to sustain & guarantee Stability.

Proposal: Based on discussions with the Engineers, we propose exploring a Platform-as-a-Service model, decoupling Platform code from Domain code. Platform owns build-to-certification; Domains own consumption-to-promotion. This shifts stability upstream, removes recurring merge overhead for Domains, provides a consistent path for hotfixes and patches, and preserves Domain autonomy.
